# DB-QP-E201 신제품 개발

## 1 목적

새 제품과 고객 맞춤 사양을 정해진 순서로 만들어서, 고객 요구와 규격을 만족하는지 확인한 뒤에 판다. 개발 과정을 남겨 다음 개발과 인증의 근거로 쓴다.

## 2 적용 범위

다음 세 가지에 적용한다.

- 신제품 개발: 새로 만드는 제품이나 기존 제품의 새 규격(예: 인공어초 시제품)
- 맞춤 사양: 고객이 제시한 사양으로 만드는 제품(예: 맞춤형 논슬립, 제품 코드 접미사 X)
- 신규 취급품목: 직접 만들지 않고 들여와 파는 품목을 새로 더하는 것(예: 에코앤시티 카탈로그 검토)

## 3 용어

| 용어 | 뜻 |
|---|---|
| 개발 입력 | 무엇을 만들지 정하는 조건. 고객 요구, 기능, 사용 환경, 법규, 관련 규격 |
| 개발 출력 | 개발 결과물. 제품 사양, 규격서 초안, 검사 기준 |
| 검증 | 결과물이 개발 입력을 만족하는지 측정과 시험으로 확인하는 것 |
| 유효성 확인 | 시제품을 실제 현장에 시공해서 쓸 수 있는지 확인하는 것 |

## 4 책임

| 역할 | 책임 |
|---|---|
| 실장 | 개발 착수 결정, 개발 입력·출력 승인, 출시 결정, 외부 유출 허가 |
| 생산팀장 | 시제품 제작, 자체 측정, 현장 시공 시험, 생산 가능성 검토 |
| AI | 개발 기록 정리, 시장·규격·경쟁 제품 조사, 규격서·등록 서류 초안 |

## 5 업무

### 5.1 착수

- 고객 요구, 현장 조사, 시장 변화에서 개발 거리가 나오면 실장이 착수 여부를 정한다.
- 착수하면 위키 디자인연구소에 개발 페이지를 하나 만든다. 이 페이지가 그 개발의 기록이 된다.

### 5.2 개발 입력

개발 페이지에 다음을 적는다.

- 고객의 요구
- 제품의 기능
- 사용 환경(법면·보행로·수중 등)
- 법적 조건
- 관련 규격(단체표준, 조달 규격서)

고객이 사양서나 규격서를 주면 그것으로 갈음한다. 조건이 분명하지 않거나 서로 어긋나면 실장이 고객과 직접 정리한다.

### 5.3 시제품과 검증

1. 생산팀장이 시제품을 만든다.
2. 개발 입력의 항목을 자체 측정으로 확인한다. 자체 측정이 어려운 항목은 공인기관 시험으로 확인한다.
3. 결과를 개발 페이지에 적는다. 맞지 않으면 사양을 고쳐 다시 만든다.

### 5.4 유효성 확인

시제품을 실제 현장에 시공해서 확인한다. 현장 사진과 결과를 개발 페이지에 남긴다.

### 5.5 출시

실장이 출시를 정하면 다음을 한다.

- 제품 사양과 검사 기준을 정한다. 조달 판매 품목은 규격서를 만들어 물품식별번호를 등록한다(예: 2026-02 신규 논슬립 5품목).
- 품목을 품목마스터에 올린다.
- 첫 생산분은 검사 및 시험(DB-QP-F103)의 제품검사를 받는다.

### 5.6 맞춤 사양

고객 사양이 기존 제품의 규격 안이면 견적과 함께 실장이 승인하고 바로 생산한다. 규격 밖이면 5.2~5.4를 줄여서 거친다.

### 5.7 신규 취급품목

들여와 파는 품목을 더할 때는 실장이 공급처의 규격, 시험성적서, 단가를 검토하고 정한다. 공급처는 거래처관리(DB-QP-E302)에 따라 등록한다.

### 5.8 변경

개발 중이나 출시 뒤 사양을 바꾸면 바꾼 내용과 이유를 개발 페이지에 적고 실장 승인을 받는다. 출시된 제품의 변경은 변경관리(DB-QP-F302)에 따른다.

### 5.9 보안

도면, 시방, 개발 기록은 업무 밖으로 내보내지 않는다. 내보낼 일이 있으면 실장 허가를 받는다.

| 규격서·물품식별번호 | 조달 등록본(로컬 사본은 참조만) | 등록·변경 시 | 영구 |
